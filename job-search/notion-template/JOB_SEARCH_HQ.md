## Pattern Templates

<details>
<summary>🔄 Sliding Window Template</summary>

```python
def sliding_window(s):
    window = {}
    left = 0
    result = 0

    for right in range(len(s)):
        # Expand: add s[right] to window
        window[s[right]] = window.get(s[right], 0) + 1

        # Shrink while invalid
        while not is_valid(window):
            window[s[left]] -= 1
            if window[s[left]] == 0:
                del window[s[left]]
            left += 1

        # Update result
        result = max(result, right - left + 1)

    return result
```

</details>

<details>
<summary>🔍 Binary Search Template</summary>

```python
def binary_search(nums, target):
    left, right = 0, len(nums) - 1
    while left <= right:
        mid = left + (right - left) // 2
        if nums[mid] == target:
            return mid
        elif nums[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1
```

</details>

<details>
<summary>🌳 BFS Template</summary>

```python
from collections import deque

def bfs(root):
    if not root:
        return []

    result = []
    queue = deque([root])

    while queue:
        level_size = len(queue)
        level = []

        for _ in range(level_size):
            node = queue.popleft()
            level.append(node.val)

            if node.left:
                queue.append(node.left)
            if node.right:
                queue.append(node.right)

        result.append(level)

    return result
```

</details>

## Quick Reference Cards

### Seller Payment System
<details>
<summary>💳 Seller Payment System</summary>

**One-liner**: Async payment system for sellers with aggregated payouts and idempotent processing.

**Architecture**:
```
OrderService → Queue → BalanceService → PayoutScheduler → PaymentProcessor → Gateway
```

**Key Components**:
- Order Consumer: Process order events
- Balance Service: Track pending/available balance
- Payout Scheduler: Trigger based on schedule
- Payment Processor: Execute with retry

**Key Decisions**:
1. Aggregate per seller per cycle → fewer fees
2. Idempotency key → no duplicates
3. State machine → exactly-once
4. 7-day settlement window

**State Machine**:
```
PENDING → PROCESSING → COMPLETED
              ↓
            FAILED → PENDING (retry)
              ↓
           CANCELLED (max retries)
```

</details>

### Financial Clearing House
<details>
<summary>🏦 Financial Clearing House</summary>

**One-liner**: Interbank settlement using multilateral netting to minimize transfers.

**Algorithm**:
1. Calculate pairwise balances between all bank pairs
2. Compute net position per bank
3. Greedy match largest creditor with largest debtor
4. Generate minimum transfers (N-1 for N banks)

**Example**:
```
9 transactions, $5,757 gross
After netting: 2 transfers, $387
Efficiency: 93.3%
```

**Key Decisions**:
- Decimal for amounts (no floating-point errors)
- Immutable transactions (audit trail)
- Greedy heap-based netting O(N log N)

</details>

### Uber Eats Feed
<details>
<summary>🍔 Uber Eats Feed</summary>

**One-liner**: Geo-indexed restaurant feed with personalized ranking at 10K+ QPS.

**Architecture**:
```
Client → API Gateway → Geo Cache → Geo Index (ES) → Ranking → DB
```

**Spatial Indexing (H3)**:
- Resolution 8: 461m (urban)
- Resolution 9: 174m (dense areas like Manhattan)
- Why H3: Hexagons approximate circles better

**Caching**:
- Geo-cell IDs: 60s TTL, 80% hit rate
- Restaurant details: 5min TTL

**Ranking Formula**:
```
score = w1*distance + w2*rating + w3*eta + w4*personalization
```

</details>

## SOLID Principles Cheat Sheet

| Principle | Key Idea | Example |
|-----------|----------|---------|
| **S**ingle Responsibility | One class, one job | Separate UserService, EmailService |
| **O**pen/Closed | Open for extension, closed for modification | Use interfaces for new payment types |
| **L**iskov Substitution | Subclass can replace parent | Don't break parent behavior |
| **I**nterface Segregation | Small, focused interfaces | Split fat interfaces |
| **D**ependency Inversion | Depend on abstractions | Inject Database interface, not MySQL |
