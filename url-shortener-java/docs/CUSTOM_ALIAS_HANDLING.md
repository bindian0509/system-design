# Custom Alias Handling in Global Multi-Region Deployment

## Overview

This document explains how custom aliases (user-defined slugs) are handled in a globally distributed URL shortener, where auto-generated codes use region-based range allocation.

## The Challenge

When a user requests a custom alias like `my-brand` or `sale2024`, it creates a potential conflict scenario with the auto-generated codes from the distributed counter system.

### Key Differentiators

| Aspect | Auto-Generated | Custom Alias |
|--------|----------------|--------------|
| **Source** | Regional counter → Base62 | User input |
| **Format** | Exactly 7 Base62 chars | 4-50 alphanumeric + hyphens |
| **Uniqueness** | Guaranteed by range allocation | Global DB check required |
| **Region Binding** | Created in specific region | Region-agnostic |
| **Storage Flag** | `is_custom_alias: false` | `is_custom_alias: true` |

## Collision Prevention Strategies

### Strategy 1: Format Differentiation (Primary)

Auto-generated codes and custom aliases have **mutually exclusive formats**:

```mermaid
flowchart LR
    subgraph AutoFormat["Auto-Generated Format"]
        AF["Exactly 7 characters<br/>Base62 only (0-9, a-z, A-Z)<br/>Examples: 0000001, 0LY7VK3, aB3dE5f"]
    end

    subgraph CustomFormat["Custom Alias Format"]
        CF["4-50 characters<br/>Must contain: letter + (number OR hyphen)<br/>Examples: my-brand, sale2024, promo-summer"]
    end

    AutoFormat -.->|"No overlap by design"| CustomFormat
```

```java
public class AliasValidator {

    // Auto-generated: exactly 7 Base62 characters
    private static final Pattern AUTO_GEN_PATTERN =
        Pattern.compile("^[0-9a-zA-Z]{7}$");

    // Custom: 4-50 chars, alphanumeric + hyphens
    // Must have at least one letter AND one non-letter
    private static final Pattern CUSTOM_ALIAS_PATTERN =
        Pattern.compile("^(?=.*[a-zA-Z])(?=.*[0-9\\-])[a-zA-Z0-9\\-]{4,50}$");

    public boolean isValidCustomAlias(String alias) {
        if (alias == null || alias.isBlank()) {
            return false;
        }

        // Must match custom pattern
        if (!CUSTOM_ALIAS_PATTERN.matcher(alias).matches()) {
            return false;
        }

        // Must NOT look like an auto-generated code
        if (looksLikeAutoGenerated(alias)) {
            return false;
        }

        return true;
    }

    private boolean looksLikeAutoGenerated(String alias) {
        if (!AUTO_GEN_PATTERN.matcher(alias).matches()) {
            return false;
        }

        // If it's exactly 7 Base62 chars, check if it decodes
        // to a value within the auto-gen range
        try {
            long value = base62Decode(alias);
            return value >= 0 && value <= MAX_AUTO_GEN_VALUE;
        } catch (Exception e) {
            return false;
        }
    }
}
```

## Edge Cases and Solutions

### Edge Case 1: Race Condition on Custom Alias

Two users request the same custom alias simultaneously:

```mermaid
sequenceDiagram
    participant U1 as 👤 User 1 (US)
    participant U2 as 👤 User 2 (EU)
    participant US as 🇺🇸 US App
    participant EU as 🇪🇺 EU App
    participant DDB as DynamoDB

    par Simultaneous requests
        U1->>US: Create "promo"
        U2->>EU: Create "promo"
    end

    par Check existence
        US->>DDB: exists("promo")?
        EU->>DDB: exists("promo")?
    end

    DDB-->>US: false
    DDB-->>EU: false

    par Try to save
        US->>DDB: save("promo") with condition
        EU->>DDB: save("promo") with condition
    end

    Note over DDB: Conditional write succeeds<br/>for first request only
    DDB-->>US: Success ✓
    DDB-->>EU: ConditionalCheckFailed ❌

    US-->>U1: 201 Created ✓
    EU-->>U2: 409 Conflict ❌
```

**Solution: Conditional Writes**

```java
// DynamoDB conditional put
PutItemRequest request = PutItemRequest.builder()
    .tableName("urls")
    .item(itemMap)
    .conditionExpression("attribute_not_exists(short_code)")
    .build();

try {
    dynamoDb.putItem(request);
} catch (ConditionalCheckFailedException e) {
    throw new AliasAlreadyExistsException("Alias already taken");
}
```

### Edge Case 2: Custom Alias Matches Future Auto-Gen Code


**Solution: Auto-Gen Collision Check**

```java
public String generate() {
    while (true) {
        long value = counter.getAndIncrement();
        String code = encode(value);

        // Check if code already exists (could be custom alias)
        if (!repository.existsByShortCode(code)) {
            return code;
        }

        // Extremely rare: code exists, try next
        log.warn("Code collision detected: {}, trying next", code);
    }
}
```

### Key Takeaways

1. **Custom aliases exist in a separate logical namespace** - differentiated by `is_custom_alias` flag
2. **Format validation prevents most collisions** - custom aliases must differ from auto-gen pattern
3. **Global uniqueness is always checked** - DynamoDB Global Tables ensure consistency
4. **Conditional writes handle race conditions** - only one concurrent request can succeed
5. **Auto-gen codes skip existing custom aliases** - collision check during generation
6. **Cross-region access works seamlessly** - data is replicated globally
