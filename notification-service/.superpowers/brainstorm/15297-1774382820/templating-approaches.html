Templating: Inline vs Separate Service

Where should template rendering live, and how do we handle large email payloads?

A

Inline: Template rendering inside Notification Service

Notification Gateway fetches the template, renders it with vars, and embeds rendered HTML into the Kafka message before enqueuing.

Caller → Gateway → [render here] → Kafka (large msg) → Worker → SES

Pros

  • Single service to operate
  • Worker is dumb — no template dependency

Cons

  • Kafka messages become MBs (breaks 1MB limit)
  • Template logic coupled to delivery logic
  • No A/B testing or template versioning built-in
  • Marketing teams need code deploys to change templates
  • Gateway CPU hit on render (blocks quota/dedup path)
B

Separate Template Service ✦ Recommended

A dedicated Template Service handles template CRUD, versioning, A/B testing, and rendering. The Notification Service only carries {template_id + vars} through Kafka. Workers call the Template Service just before dispatch.

Caller → Gateway → Kafka ({template_id, vars} — tiny) → Worker → [render here] → SES
Large email handling: Images are CDN URLs (never base64). Rendered HTML > 256KB → stored in S3 → worker streams directly to SES. Kafka message stays < 4KB always.

Pros

  • Kafka messages stay tiny (template_id + vars only)
  • Template Service scales independently (read-heavy, cacheable)
  • Marketing teams own templates via UI — no code deploys
  • A/B testing, versioning, personalization all in one place
  • Images always CDN-hosted → email body stays small
  • S3 for rendered HTML if > 256KB threshold
  • Template cache at worker level (Redis, TTL 60s)

Cons

  • Template Service becomes a dependency of workers
  • One more service to operate
  • Template Service outage can block email sends
  • Need circuit breaker + fallback on Template Service calls

Large Email Payload Strategy (regardless of approach)

Rule 1: Images are NEVER base64 in emails — always CDN URLs (img src="https://cdn.example.com/...")
Rule 2: Rendered HTML > 256KB → upload to S3 → worker fetches S3 URL and streams to SES (SES supports raw MIME up to 40MB)
Rule 3: Kafka max.message.bytes set to 4MB as a safety net, but target is <4KB per message
Rule 4: Template Service caches rendered output per {template_id + user_segment} (TTL=60s) — bulk sends reuse same render
